## 1. Problem

In the F99c profile (variant `t` of `bench.py --scaling`, 1 thread, perf) three functions together take 5 / 18 / 54 / 81 samples at 1200 / 2400 / 4800 / 9600 rows: `pagination_layout::has_forced_break_below`, `has_page_name_change_below` and `blitz_adapter::walk_used_page_names`. `collect_position_fixed_ids` takes 2 / 4 / 12 / 16. No invoice fixture shows this, because `02-long` has only 60 rows. What shows it is `bench/corpus/b200-items.html` and `--scaling` variant `t`.

**Correction to the finding, from reading the code.** The work is not quadratic. Nothing in this path runs once per page.

- The two `has_*_below` functions run inside the recursion gate once for each in-flow child that has children. They run up to twice per child (again after a page advance), at every level the fragmenter enters: the table at body level, then `tbody`, then each row.
- Each call walks the child's whole DOM subtree. When nothing is found, which is the common case, the walk never stops early.
- So every cell's subtree is walked about 2 functions × 2 evaluations × 3 levels ≈ 12 times (estimate). Each visit does BTreeMap lookups into `column_styles` and into `used_page_names`. `used_page_names` has one entry per element and the lookup clones the entry.
- That is O(n · levels · log n), plus cache misses once the node slab is larger than the cache. The doublings fit that: ×3.6, ×3.0, then ×1.5, not ×4 each time.
- `walk_used_page_names` and `collect_position_fixed_ids` are one walk per render. `collect_position_fixed_ids` is linear by its own numbers.
- The gain is the work removed, not a lower exponent: about 40–50 ms CPU at 4800 rows on the 2.80 GHz host (estimate: 54 + 12 perf samples, minus perf's ~15 % overhead).

## 2. Spec

This change is speed only, and every PDF must stay byte-identical. I had no `css-spec-researcher` output. The references below come from fulgur's comments and from memory, and are all **unverified**. They are the semantics the changed code must keep:

- **css-break-3 §3.1**: `break-before` / `break-after` values `page | left | right | recto | verso` are forced page breaks. fulgur folds them all into `Page` (`column_css.rs:475-478`).
- **css-break-3 §4.1 and §4.3**: break classes, and a forced break wins over `avoid`. This is what the gate is for.
- **css-page-3, `page` property ("§5.3" in fulgur)**: there is a forced break between adjacent boxes whose used page names differ. Flex and grid items, atomic inlines and out-of-flow boxes are excluded (`blitz_adapter.rs:920-956`).
- **css-writing-modes-4 §7.3**: orthogonal flows are atomic for page names.
- **css-display-3 `display: contents`**: the walks follow DOM `children`, so the contents element is walked like any other node. The table must do the same.
- **CSS 2.1 §9.3.1 / §10.1.5** (`position: fixed`) and **§9.5** (floats are out of flow).

### 3.2 Decision

1. **`SubtreeFacts`**, a new file `crates/fulgur/src/pagination_layout/subtree_facts.rs`:

   ```rust
   pub(crate) struct SubtreeFacts {
       forced_level: Option<Vec<u16>>,    // None: column_styles has no forced break at all
       page_name_level: Option<Vec<u16>>, // None: no used page-name table
   }
   pub(crate) const NO_LEVEL: u16 = u16::MAX;
   impl SubtreeFacts {
       pub(crate) fn build(doc: &BaseDocument, column_styles: Option<&ColumnStyleTable>,
                           used_page_names: Option<&UsedPageNameTable>) -> Self;
       pub(crate) fn forced_break_below(&self, node_id: usize) -> bool;      // == has_forced_break_below(.., 0)
       pub(crate) fn page_name_change_below(&self, node_id: usize) -> bool;  // == has_page_name_change_below(.., 0)
   }
   ```

   **How it is built.**
   - Each `Vec` is indexed by Blitz slab key. Its length is 1 + the largest occupied key, and vacant keys hold `NO_LEVEL`.
   - It is filled by one memoised, iterative post-order DFS over `children` edges, started from every key of `doc.tree()` in key order. No recursion, so no depth limit.
   - **Every slab node has to be covered, not only the nodes reachable from the root.** Blitz's anonymous block wrappers are reachable only through `layout_children`, and the gate does query them. Their `children` are nodes that also belong to the real parent (`construct.rs:518-528`), so the graph is a DAG.

   **The two levels.** Both depend only on the node itself, so the DAG is safe:
   - `flevel(n)` = the minimum over the children `c` of `1` if `c` has a forced break, else `flevel(c) + 1`. It is `NO_LEVEL` for a node with no children or a missing node.
   - `plevel(n)` = `NO_LEVEL` if `n` is opaque; `0` if `local(n)` holds; otherwise the minimum over the filtered children `c` of `plevel(c) + 1`.
     - `local(n)` means: `n` is not a flex or grid container, and two consecutive filtered children differ in `prev.end != cur.start`.
     - "Filtered children" and "opaque" use the same predicates, in the same order, as `:2818-2889`.
   - Additions saturate at `NO_LEVEL`.

   **Queries.**
   - `forced_break_below(n)` = `flevel(n) <= MAX_DOM_DEPTH`.
   - `page_name_change_below(n)` = `plevel(n) < MAX_DOM_DEPTH`.
   - A `None` vector, or a node id out of range, answers `false`.

   **Fast paths, all exact.**
   - If `column_styles` has no `Page` value, `forced_level` is `None` and nothing is walked.
   - If `used_page_names` is `None`, `page_name_level` is `None`.

2. **Wiring.**
   - `PaginationLayoutTree` gets `subtree_facts: Option<SubtreeFacts>`. `run_pass_inner` builds it right after `used_page_names`, from the same two tables.
   - `fragment_block_subtree` gets one new parameter, `facts: Option<&SubtreeFacts>`, which it passes on unchanged at `:3992`.
   - Both gates call these helpers:

     ```rust
     fn forced_break_below(facts: Option<&SubtreeFacts>, doc: &BaseDocument,
                           column_styles: Option<&ColumnStyleTable>, node_id: usize) -> bool;
     fn page_name_change_below(facts: Option<&SubtreeFacts>, doc: &BaseDocument,
                               used_page_names: Option<&UsedPageNameTable>, node_id: usize) -> bool;
     ```

     With `None` they run the old walk, which stays as the oracle. With `Some` they read the table and `debug_assert_eq!` it against the walk.
   - The abspos path (`abspos_flow.rs:937`, which already passes no page names) and the test call at `:7274` pass `None`, so their behaviour does not change.

3. **Skip the used page-name table when the document has no named page.**
   - `run_pass_inner` and the test-only lazy fill change to `column_styles.filter(|cs| column_css::has_named_page(cs)).map(compute_used_page_names)`, with `pub(crate) fn has_named_page(&ColumnStyleTable) -> bool`.
   - This is exact. With no `PageName::Named` anywhere, every entry would be `(None, None)`. Every reader treats a missing table as `(None, None)` (`:1144-1148`, `:3310-3312`), and `has_page_name_change_below` returns `false` both for `None` and for an all-`None` table.
   - The field doc at `:980-988` already describes `None` this way.

4. **`collect_position_fixed_ids`**: iterate `&node.children` instead of `node.children.clone()`. The borrows are shared, and the order is the same.

**Invalidation.**
- The facts read only DOM `children`, computed styles and the two side tables. They never read `final_layout`.
- They are built at the start of `run_pass_inner` and dropped at its end. `run_pass_with_multicol` runs once per render, after `relayout_position_fixed` and the multicol pass. A second render pass (for `target-*` references) builds them again.
- The fragmenter does not change DOM or styles. The one place that writes, the test-only `drive_taffy_root_layout`, changes layout only.

**Why the answers are equal.** By induction on `d`: `has_forced_break_below(n, d)` ⇔ `flevel(n) <= MAX - d`, and `has_page_name_change_below(n, d)` ⇔ `plevel(n) < MAX - d`.
- Base case `d >= MAX`: both sides are false, because both walks bail and both levels are at least 0 (`flevel` at least 1).
- Induction step: each walk is an OR over the same children, of the same pure predicates and the same recursion at `d + 1`. The order of evaluation and the early return do not change a pure boolean.
- The gates call with `d = 0`.
- **Exception:** a DOM cycle, which html5ever and Blitz never create.

## 6. Risks and non-goals

- **The gain is small and noisy.** At most ~50 ms (estimate). The proof is the perf item and the bytes, not the wall clock.
- **The fast paths hide the table from the fixtures.** No fixture has a forced break or a named page, so `slow-breaks`, `t-names`, the oracle tests and the `debug_assert` are what cover the table path.
- **Anonymous wrappers make a DAG, and Blitz could change that.** Covering every slab key handles it, and a test queries an anonymous id. If a later Blitz version adds nodes during fragmentation, the `debug_assert` will catch it.
- **The `debug_assert` brings the walks back in debug builds.** It costs test time only; fulgur's tests use small documents.
- **Memory:** two `Vec<u16>` the size of the slab, about 0.2 MB at 4800 rows (estimate). They are allocated only when the document has forced breaks or named pages.
- **Candidates, not in this PR** (one finding per PR):
  - `avoid_piece_size` / `forced_break_offsets` (`:529-607`) walk the subtree of every avoid row. The same `flevel` could short-cut it exactly, but `facts` would have to be threaded through `leading_block_size`, `starts_with_relaxed_avoid` and `avoid_measure`, so it is not trivial.
  - `in_avoid_box(parent)` (`:3620`) does not depend on the child but runs inside the child loop. It could move out of the loop.
  - Ancestor walks in `abspos_flow.rs` (`has_guarded_ancestor :169`, `containing_block :140`, `has_ancestor_in :193`): O(depth) per abspos box, which needs facts from the top down, not from the bottom up.
  - `would_split_block_subtree` clones the children `Vec` on every gate call (`:2575-2579`).
  - `walk_used_page_names` still clones `String`s when the document has names; interning the names would fix that.
- **Non-goals:**
  - any change to output or to the break rules (F31 included);
  - the abspos flow path, which keeps the walks;
  - F145;
  - Blitz or Taffy;
  - tightening `SCALING_MAX_RATIO`.
