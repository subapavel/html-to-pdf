## Findings

### F1 — `oklch()`, `lab()`, `color-mix()` components are emitted as raw RGB  (severity: high, size: small)

`color: oklch(21% 0.034 264.665)` → content stream `0.2118 0.0353 1 rg` — i.e. L→R, C→G, H clamped→B.
`#111827` and `rgb(17 24 39)` are correct. Tailwind v4's whole palette is `oklch`, so every colour is wrong.
Where: fulgur's conversion from Stylo's `AbsoluteColor` — must convert to sRGB (`to_color_space`) before
taking components. Upstream PR candidate; carry a patch meanwhile. Acceptance: probe rows B/D/E/F equal row A/C
within 1/255; fixture 01 diff drops below 3 %.

### F2 — `@property`-registered initial values are not applied  (severity: high, size: small on our side)

Tailwind v4 declares `--tw-border-style: solid` etc. via `@property` and, for engines without it, repeats them in
`@layer properties { @supports (… -moz-orient:inline and not (color: rgb(from red r g b))) { … } }`.
Stylo is Firefox's engine: `-moz-orient` matches and relative colour syntax is supported, so the fallback block is
*skipped*, and Blitz does not implement `@property`, so the custom properties stay unset → `border-style: initial`
→ **no borders anywhere**, gradient stops unset → no gradients, `--tw-leading`, `--tw-font-weight` … likewise.
Plain `border-bottom: 2px solid` and `linear-gradient(...)` render fine, so this is purely the defaults mechanism.
Fix options: (a) our layer prepends a generated "Tailwind compat prelude" that sets the `@property` initial
values unconditionally (extract them from `tailwind.css` at build time); (b) `@property` support in Blitz/Stylo
integration (upstream, larger). Do (a) now, file (b).

### F3 — text with no matching font is silently dropped  (severity: critical — data loss, size: small)

`font-family: monospace` with no monospace font bundled renders nothing; `pdftotext` confirms the text is absent.
In fixture 01 the bank account, IBAN and variable symbol disappear. Fix in our layer: always bundle a fallback
font and map the generic families (`monospace`, `sans-serif`, `serif`, `ui-monospace` …) to bundled faces;
error out loudly if a document uses a family we cannot resolve. Upstream: Parley/Blitz should fall back to any
available face rather than drop the run.

### F7 — the engine evaluates media queries as `screen`, not `print`  (severity: high for Tailwind, size: unknown — upstream)

Found by `vrt-validator` on PR #1: rules inside `@media print` do not apply, rules inside `@media screen` do.
For invoices this is backwards: Tailwind's `print:` variants are ignored and screen-only rules leak into the PDF.
fulgur had a PR for `@media print` support in Blitz (#390), so the switch may be a one-liner on the fulgur side;
verify in `blitz_adapter.rs`, then fork + `[patch.crates-io]` per the standing decision. Acceptance: a probe with
`@media print { p { color: red } } @media screen { p { color: blue } }` renders red; fixture 05's `print:bg-slate-900`
applies.

### F8 — gradients with a colour-interpolation method are dropped  (severity: medium, size: unknown — upstream)

Found while doing F2. `linear-gradient(to right in oklab, red, blue)` paints nothing; the same gradient without
`in oklab` renders, also when built through `var()`. Tailwind v4 always emits `--tw-gradient-position: to … in oklab`,
so every `bg-gradient-*` is lost (05's header and totals box). Probe: `out/scratch/g.html` in the F2 PR description.
Spec: css-images-4 §3.1 `<color-interpolation-method>`. Where: Stylo parse (likely another static pref, check
`stylo_static_prefs`) or Blitz's gradient paint. Acceptance: probe rows 2/3/5 equal row 1; 05's header is a gradient.

### F4 — `text-transform` ignored  (severity: medium, size: medium)

`uppercase` headings render as source text. Upstream (fulgur paragraph/Parley path). Workaround for templates:
write the text in capitals.

### F5 — table auto layout differs from Chrome  (severity: medium, size: large — upstream)

Fixed `w-*` columns are honoured, but the remaining width is distributed differently, so the description column
is narrower, rows wrap, and 02-long paginates to 4 pages instead of 3. Known: Taffy has no table algorithm.
Mitigation for invoices: set explicit widths on all columns (`table-fixed` + `w-*`), which is also better practice
for print. Upstream issue to track.

### F6 (expected) — gradients via Tailwind, `shadow-*`, `ring-*`, `@page { margin: 0 }` full-bleed  (05-fancy)

Gradients are F2. Shadows: fulgur has outer `box-shadow` (v0.4.5+) but 05 shows none — investigate after F2
(the `--tw-shadow` custom properties are also `@property`-registered, so likely the same root cause).

### F9 — `<img>` without explicit `width`/`height` attributes is not rendered  (severity: high, size: unknown)

Probe (`out/scratch` style, PNG registered via `--image logo.png=…`): `<img src="logo.png" width="120" height="36">`
renders; `<img src="logo.png" style="height:48px;width:auto">` and a bare `<img src="logo.png">` render nothing —
the image object is not even emitted. Intrinsic size / aspect ratio of the decoded image is not used for layout.
Hits fixture 03 (`h-12 w-auto` logo). Workaround for templates: always set `width` and `height` attributes.
Acceptance: all three probe variants show the image; 03 shows the logo at 48 px high, aspect kept.

### F10 — malformed CSS panics in fulgur's `::marker` rewrite  (severity: high — crash on user input, size: small — upstream)

Found by `vrt-validator` on PR #3: a `<style>` with an unterminated block that mentions `::marker`, e.g.
`<style>a::marker{color:red</style>`, panics in fulgur 0.40.0 `blitz_adapter.rs:3371`
(`rewrite_marker_content_url`, range end out of bounds). Independent of F7 (that text is not rewritten).
Fix upstream (bounds check); until then consider catching the panic at our API boundary (`catch_unwind`) and
returning an error. Acceptance: the repro returns `Err`, never panics.

### F11 — `none` colour components are mis-converted  (severity: low — Tailwind never emits it, size: small — fork)

Found by `vrt-validator` on PR #8 (F1). `oklch(50% none 0)`, `oklab(50% 0 none)`, `lab(50% none 0)` and
`color(display-p3 none .5 .5)` paint black; `lch(50% 40 none)` / `oklch(70% 0.1 none)` lose their chroma (grey). They
should behave as if `none` were 0 (css-color-4 §4.4). Likely in Stylo's `to_color_space` on `none` (NaN?) components
before `into_srgb_legacy` clears the flags; fix in the fulgur fork (zero `none` components before converting).
Repro: `/tmp/claude-0/vrt-f1/p/none.py` in the PR #8 session.

### F12 — `<thead>` is not repeated on continuation pages  (severity: medium, size: unknown — fulgur pagination)

Found in F5. Chrome repeats a table's header group on every page the table spans (CSS 2.1 §17.2, `table-header-group`: "print user agents may repeat header rows on each page"; Chrome,
Prince and WeasyPrint do). 02-long prints the column headings only on page 1, so
pages 2–3 have unlabelled columns and every row sits one header row higher than in Chrome. Acceptance: 02 pages 2–3
start with the header row; worst-page diff of 02 drops.

### F13 — table cells are top-aligned instead of `vertical-align: middle`  (severity: low, size: small — Blitz)

Found in F5 (`out/compare/02-long-p2.png`). The HTML UA stylesheet gives `thead`, `tbody`, `tr` `vertical-align:
middle`, cells inherit it (HTML §15.3.8). In 02 the quantity and price cells of a row whose description wraps sit on
the first line; Chrome centres them. Acceptance: a two-line row in 02 has its numbers centred between the lines.

### F14 — `calc()` with a percentage as a table cell width panics  (severity: high — valid CSS refused, size: small — Blitz)

Found by `vrt-validator` on PR #10 (F5). A first-row cell with `width: calc(10% + 20px)` reaches `_ => unreachable!()`
in blitz-dom `layout/table.rs` (`collect_table_cells`); we catch it and return `Error::EnginePanic`. Expected: the
width is treated as `auto` (css-values-4 makes this a MUST for table cells; Chrome, Firefox and WebKit agree).
Repro: `<table><tr><td style="width:calc(10% + 20px)"></td><td></td></tr></table>`.

### F15 — table column algorithm gaps beyond F5  (severity: low for invoices, size: large — Blitz)

Found by `vrt-validator` on PR #10. Blitz derives one column per first-row cell and ignores: `colspan` in the first
row (column count wrong), `rowspan` when placing later cells, `min-width` on cells, `<col>`/`<colgroup>` widths,
percentages summing over 100 %, and min-content growth of a column whose explicit width is narrower than its
content (Chrome widens it; we overflow). Probes: `/tmp/claude-0/vrt-f5/` in the PR #10 session. Split into separate
findings when one hits a fixture.
More from `vrt-validator` on PR #11 (probes `/tmp/claude-0/vrt-f14/`), all pre-existing: `width: 0%` makes a 0 px
column (Chrome: padding + border); percentage columns summing below 100 % leave the table short; any `width` on
`<tr>`/`<tbody>` changes column widths (Chrome ignores it; css-values-4 also makes a mixed `calc()` row width
`auto`); cell `min-width`/`max-width` differ from Chrome; `table-layout: fixed` still takes widths from later rows;
`display: inline-table` renders nothing.

### F19 — `<tr>` / row-group backgrounds are not painted: 03's total is white on white  (severity: high — the amount due is invisible, size: small–medium — Blitz/fulgur)

Found by `pdf-reviewer` on PR #13. Fixture 03's `<tr class="bg-gray-900 text-white">` "Celkem k úhradě 48 400,00 Kč"
(in `<tfoot>`) prints white text on a white page: the text is in the PDF (`pdftotext` finds it) but the row's
background is never painted. Blitz flattens `thead`/`tbody`/`tfoot`/`tr` out of the table grid (zero-size boxes), so
fulgur has nothing to paint. CSS 2.1 §17.5.1 (table layers): row-group and row backgrounds paint under the cells of
that group/row. Acceptance: 03's total row is dark with white text, as in Chrome; a `<tr>` and a `<tbody>` with a
background paint behind their cells on every page they span.

### F20 — tagged PDF: cell and margin-box text is outside marked content  (severity: low until PDF/UA is on the roadmap, size: medium — fulgur)

Found by `pdf-reviewer` on PR #13 (pre-existing): `/TH` and `/TD` have empty `/K`, so cell text is neither tagged
nor an artifact; margin-box text ("Strana N / M") is outside marked content; `/Figure` has `/Alt` but empty `/K`.
Conflicts with PDF/UA-1 §7.1. A repeated `thead` could be typed `/Pagination` (ISO 32000-1 §14.8.2.2.2).

### F21 — `border-spacing` has no layout effect  (severity: low — Tailwind tables use `border-collapse` or 0 spacing, size: small — Blitz)

Found while planning F19. Blitz 0.2.4 never maps `border-spacing` to the table grid's gaps (only `column-gap` /
`row-gap` reach Taffy), so cells always abut. CSS 2.1 §17.6.1. Acceptance: the ignored test
`row_backgrounds.rs::border_spacing_gap_is_not_painted` passes.

### F22 — row and row-group borders are not painted (`border-b` on `<tr>`, `divide-y` on `<tbody>`)  (severity: medium — 01, 02, 04, 05 row rules, size: large — Blitz #386 / fulgur)

Found while planning F19. Borders on `<tr>` and row groups only exist in the collapsing border model, which Blitz
does not implement (Blitz #386). Main remaining diff of 01, 02 and 04. Needs collapsed-border resolution (CSS 2.1
§17.6.2), not just painting.

### F23 — `background-image` raster tiles are 4/3 too large  (severity: medium, size: small — fulgur, px↔pt)

Found by `vrt-validator` on PR #14 (pre-existing). A 40×40 px PNG without a pHYs chunk as `background-image` tiles
every 26.7 px instead of 20 px at the probe's 2× scale — the intrinsic size is read as pt where px was meant (or
the reverse). Rows inherit it since F19. Probe `out/scratch/v_img2.html` (PR #14 session).

### F24 — a `width: 100%` table overflows its container's padding  (severity: medium, size: unknown — Blitz/fulgur)

Found by `vrt-validator` on PR #14 (pre-existing). `body { padding: 20px }` + `<table class="w-full">`: the table
reaches 20 px past the right content edge (Chrome stops at it). Probe `out/scratch/v_w.html`.

### F25 — `background: url(data:image/svg+xml,…)` renders nothing  (severity: low, size: small — fulgur)

Found by `vrt-validator` on PR #14 (pre-existing), on `<div>`, `<tr>`, `<tbody>` alike. Registered PNGs work.

### F28 — consecutive tables do not paginate: rows past the first page are silently dropped  (severity: high — data loss, size: unknown — fulgur pagination)

Found by `vrt-validator` on PR #15, confirmed with the pre-F13 binary: 60 one-row `<table>`s in a row render on **one**
page with 50 of 60 rows (Chrome: 2 pages, 60 rows); the same 60 rows as `<p>` paginate correctly (3 pages). With or
without a wrapping `<div>`. Invoices with an items table, a VAT summary table and a totals table that cross a page
boundary would lose content. Repro: 60 × `<table><tr><td>RadekNN</td><td>B</td></tr></table>`, count `RadekNN` in
`pdftotext`. Acceptance: every row present exactly once, page count matches Chrome.

### F29 — a first child's `margin-top` collapsing through `<body>` is not counted when paginating  (severity: medium — content drawn below the page, size: small–medium — fulgur)

Found by `vrt-validator` on PR #16 (pre-existing). `<body style="margin:0">` + three `<p style="margin:500px 0 0">`: the
second `<p>` is drawn at y = 1033 px on page 1 (content box 1009 px), Chrome puts it on page 2. `body{padding-top:1px}`
fixes it. Realistic trigger: `h1.mt-8` as the first child with `body{margin:0}`. Probes `/tmp/claude-0/vrt-f28/`
(`ct_m_top_big.html`, `c_m_top_big.html`).

### F30 — content lost inside fragmented containers  (severity: high — data loss in edge layouts, size: large — fulgur)

Found by `vrt-validator` on PR #16 (pre-existing, same in the pre-F28 build): `columns:2` keeps 124 of 200 rows
(`cols2.html`); a `display:table` wrapper around tables drops everything (`wr_dtable.html`, 0 of 60); an inline-block
wrapper loses ≈20; a paragraph taller than a page inside a `div` / `li` / `td` loses its tail (at body level it splits
correctly); absolutely positioned elements inside fragmented containing blocks can vanish (`abs.html`). Split into
separate findings when one is picked up; the paragraph-in-div case is the most likely in invoices (long notes).

### F31 — `break-before: page` on a first child or on a `<tr>` is ignored  (severity: low, size: small — fulgur)

Found by `vrt-validator` on PR #16 (pre-existing). Also: negative `margin-top` ignored; `@page { size; margin }` in the
document overridden by the renderer's defaults (see F6).

### F32 — image sizing gaps beyond F9  (severity: medium, size: medium — fulgur/Blitz)

Found by `vrt-validator` on PR #17 (mostly pre-existing, reachable by bare `<img>` since F9; probes
`/tmp/claude-0/vrt-f9/p/`):
- an `<img>` wider than the content box is not painted at all (no XObject) — without Tailwind's `max-width:100%`, a
  700 px image vanishes at the default margin; a truncated PNG fails the whole render (Chrome draws it partially);
- an image taller than a page is drawn whole on the last page instead of the remainder;
- inline images don't grow the line box (lines overlap them);
- `object-fit` / SVG `preserveAspectRatio` not implemented (96×96 instead of letterboxed 96×48);
- ratio applied when both axes are given (`width:200px; max-height:30px` → 60×30, Chrome 200×30), `aspect-ratio: auto 1/1`,
  `width`/`height` attributes overriding preflight `height:auto`, `height: 50%` in an auto-height parent → 0;
- `src` matching is exact-key: `logo.png?v=1`, `#frag`, `sub/../logo.png`, surrounding spaces render nothing silently
  (HTML strips whitespace; Chrome resolves the others) — at least warn on an unregistered `src`;
- unsized SVG / `<canvas>` defaults (Chrome 300×150), SVG `width="50%"`/`em`, SVG `<img>` text dropped (no fonts),
  EXIF orientation, `float` on `<img>` ignored, abspos `left+right` stretch.
Split when picked up; the wider-than-page and unregistered-`src` cases come first (content silently missing).

### F33 — outside list markers (`list-style: disc` outside) are not painted  (severity: medium — Tailwind `list-disc` bullets missing, size: small — fulgur)

### F34 — `flex justify-end` around a fixed-width table misplaces it and drops a `border-t-2` total row  (severity: medium, size: unknown)

### F35 — cells next to a split cell: `vertical-align: middle/bottom` text lost, row/cell backgrounds wrong  (severity: medium, size: medium — Blitz F13 offset × fulgur fragmenter)

Found by `vrt-validator` on PR #18 (pre-existing, same in the pre-F30 build): in a row whose `<td><p>` is taller than a
page, a sibling cell with `vertical-align: middle` or `bottom` loses its text (its offset lands past the page); a

### F36 — `<tfoot>` is printed right under the header, before the body rows  (severity: medium — visible on any table with a footer, size: small — Blitz)

Found by `vrt-validator` on PR #18 (pre-existing): Blitz places table cells in DOM order, so a `<tfoot>` written before
`<tbody>` (the HTML4 pattern) renders between header and body; Chrome renders it at the bottom (and repeats it per
page, F12b). Probes `out/scratch/val/d6*.html`, `e1-foot-short.html`.

### F26 — `vertical-align: baseline` in table cells is treated as `top`  (severity: low, size: medium — Blitz)

Split from F13. CSS 2.1 §17.5.3: baseline cells align their first-line baselines and the row may grow. Differs from
`top` only when a row's baseline cells have different first-baseline offsets (fonts, padding, borders).

### F27 — the `valign` attribute on `td`/`th`/`tr` is ignored  (severity: low — Tailwind uses classes, size: small — Blitz)

Split from F13. HTML §15.3.8 maps `valign` to `vertical-align`; Blitz's attribute mapping (`stylo.rs`) only maps
`align`.

### F12b — `<tfoot>` is not repeated at the bottom of each page  (severity: low — no fixture, size: medium — fulgur)

Split from F12. Blitz places footer cells in DOM order (a `tfoot` before `tbody` lands on top), and repeating it
needs space reserved at the bottom of every page but the last.

### F16 — `none` across colour-space conversions in `color-mix()`, relative colours and gradients  (severity: low — Tailwind never emits `none`, size: medium — Stylo / fulgur)

Found by `vrt-validator` on PR #12 (F11). Stylo 0.8.0 `AbsoluteColor::to_color_space` carries a missing component as
NaN instead of applying css-color-4's analogous-component rules, so `color-mix(in oklab, oklch(70% 0.2 none), …)`,
`rgb(from oklch(70% 0.2 none) r g b)` and `color-mix(in srgb, white, oklch(none none none))` differ from Chrome; legacy
`rgb()` `none` and `none` alpha lose "missing" semantics in mixes. fulgur gradients neither carry a `none` stop
component from the neighbouring stop (css-color-4 §12) nor honour `in <space>`. Probes `/tmp/claude-0/vrt-f11/`
(`probe.py c3.txt bg`, `grad.py c4.txt g1`).

### F17 — non-sRGB colours in SVG presentation attributes and SVG CSS paint black  (severity: medium, size: small — Blitz)

Found by `vrt-validator` on PR #12. `<rect fill="oklch(…)">`, `style="fill:oklch(…)"`, `stop-color="oklch(…)"` and
`<style>rect{fill:currentColor}</style>` with an `oklch()` `color` paint black: usvg parses these itself and does not
know `oklch()`/`lab()`. The F1 fix only covers `currentColor` serialised for the `<svg>` element. Tailwind
`fill-*`/`stroke-*` utilities on SVG children emit `oklch()`. Expected: the sRGB equivalent, as in Chrome.

### F18 — paint gaps seen while probing colours  (severity: medium for 05, size: unknown — fulgur)

Found by `vrt-validator` on PR #12, unrelated to colour conversion: `box-shadow` blur is not rendered (hard-edged
shadow; Tailwind `shadow-*` all blur, hits 05); `outline` paints nothing; `opacity` on an inline `<svg>` is applied
twice (`.5` → 0.25); an SVG `data:` URI background with `currentColor` renders blank. Split when one is picked up.
