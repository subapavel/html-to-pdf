## 1. Problem

Blitz turns a table into a Taffy grid in **DOM order**:

- `collect_table_children` walks the table's slots in source order (`layout/table.rs:697-715`);
- each row takes the next grid line (`collect_row`, `grid.row += 1`, `:732`; cells `:415-418`);
- the table's `layout_children` are the cells in that same order (`:157-161`).

`TablePart::RowGroup` merges `table-row-group`, `table-header-group` and `table-footer-group` (`:559-561`), so nothing ever moves a header or footer group. The HTML4 pattern (`<thead><tfoot><tbody>`, required by HTML 4.01 and still generated by older ERP templates) therefore prints "Základ daně / DPH / Celkem k úhradě" straight under the column headings, above the items. Chrome prints it after the last item. A `<thead>` written after `<tbody>` goes to the bottom for the same reason.

No fixture shows the bug today:

- 03 has `thead`, `tbody`, `tfoot` in modern order (`03-logo-qr/index.html:50-88`);
- 02, 17 and the bench corpus have only `thead` first;
- the validator's probes (`out/scratch/val/d6*.html`, `e1-foot-short.html`) are gone.

Repro: `<table><thead><tr><th>H</th></tr></thead><tfoot><tr><td>F</td></tr></tfoot><tbody><tr><td>B</td></tr></tbody></table>` prints H, F, B. Chrome prints H, B, F.

Expected on main, from reading (step 0 measures each one):

| # | Shape | Main | Chrome (to confirm) |
|---|---|---|---|
| T1 | `thead, tfoot, tbody` | H F B | H B F |
| T2 | `thead, tbody, tfoot` (modern) | H B F; on a multi-page table F is on the last page only, not repeated | same, F repeated per page (F12b) |
| T3 | `tbody, thead` | B H; F12 does not repeat it (prefix check, `pagination_layout.rs:4652-4655`) | H B, H repeated |
| T4 | `display:table` divs, `table-footer-group` first | F B | B F |
| T5 | `tfoot#1, tbody, tfoot#2` | F1 B F2 | B F2 F1 |
| T6 | `<tfoot style="display:table-row-group">` first; `<tbody style="display:table-footer-group">` first | stays first; stays first | stays first; goes last |
| T7 | T1 with 120 body rows | F on page 1, H repeated | F after row 120 on the last page |
| T8 | `<caption>` + T1 | caption on top | caption on top |

## 2. Spec

Cited from memory and **unverified**. The 17.2 wording matches the F12 plan's quote.

- **CSS 2.1 §17.2.**
  - `table-header-group`: "always displayed before all other rows and row groups and after any top captions".
  - `table-footer-group`: "always displayed after all other rows and row groups and before any bottom captions".
  - For both: "If a table contains multiple elements with 'display: table-footer-group' [header-group], only the first is rendered as a footer [header]; the others are treated as if they had 'display: table-row-group'".
  - Print user agents may repeat both on each page (F12, F12b).
- **css-display-3 §2.4.** The table role comes from the computed `display`, not the tag. Blitz and fulgur already follow this (`table_part_of` `:535`, `first_table_header_group` `blitz_adapter.rs:1079`).
- **CSS Tables 3** (header/footer groups; section number unverified): same placement rule. In fixed layout the column widths come from "the first row", which I read as the first row in visual order. Step 0 checks Chrome.
- **HTML §15.3.8** (`tfoot { display: table-footer-group }`). **HTML §4.9.7** places `tfoot` last in the content model, but the parser keeps the author's order, so rendering is CSS's business. **HTML 4.01 §11.2.3** required `TFOOT` before `TBODY`.
- **ISO 32000-1 §14.8.4.3.4** (THead / TBody / TFoot). I know of no ordering requirement on the structure elements.

## 3. Where it belongs

| Option | Decision |
|---|---|
| **A. Blitz fork:** reorder the table's slots by role before building the grid | **Chosen.** This is engine behaviour, and it belongs where the box tree is built. |
| B. Blitz: keep DOM order but give rows out-of-order grid lines | Rejected. `layout_children` would no longer be ascending in y. fulgur's fragmenter places children in walk order (`fragment_block_subtree`, `pagination_layout.rs:3159-3169`, `:3242-3260`), and F12 needs header cells as a prefix (`:4652`). |
| C. fulgur: reorder at pagination or paint time | Rejected. Layout would still be wrong, and every consumer of geometry would need fixing. |
| D. Ours: move the `<tfoot>` in the DOM before rendering | Rejected. It rewrites the author's DOM (`:last-child`, `tbody + tfoot` selectors) and hides an engine bug. |

**Blitz** (`packages/blitz-dom/src/layout/table.rs`):

- New items:
  - `#[derive(Clone, Copy, PartialEq, Eq, Debug)] pub(crate) enum GroupRole { Header, Footer }`
  - `fn group_role_of(node: &Node) -> Option<GroupRole>`: from the computed display (`DisplayInside::TableHeaderGroup` / `TableFooterGroup`, `outside != None`).
  - `pub(crate) fn order_table_slots(slots: Vec<Slot>, roles: &[Option<GroupRole>]) -> Vec<Slot>`, a pure function:
    - the first `Slot::Keep(i)` with role `Header` goes to the front;
    - the first with role `Footer` goes to the end;
    - everything else keeps its relative order: further header/footer groups, body groups, bare rows and anonymous rows.
- `collect_table_children` (`:680`), at `Level::Table` only: compute `roles` next to `parts` over the same flattened `ids` (so `display: contents` is respected, `:688`), then iterate `order_table_slots(plan_table_children(..), &roles)`.
  - Rows, cells, grid lines and the table's `layout_children` then all come out in visual order. No other function changes.
  - **Consequence 1:** "the first row" that sets column widths (`push_cell_item`, `grid.row == 1`, `:378-397`) becomes the first *visual* row. That is intended (§2), and step 0 checks it against Chrome.
  - **Consequence 2:** `<caption>` is untouched. fulgur moves it out of the table before Blitz sees it (comment at `:499`), and `Caption` is skipped anyway.

**fulgur fork:** no behaviour change. With Blitz's new order:

- F12's prefix check holds for a `thead` written after `tbody`, so that header now repeats. This is Chrome's behaviour.
  - `table_with_tbody_before_thead_is_not_repeated` (`pagination_layout.rs:11421-11436`) flips. It becomes `table_with_tbody_before_thead_repeats_its_header`.
  - Update the doc comments that say "in DOM order" (`:4490-4495`, `:4612-4614`).
- Add a lib test: in a `tfoot`-first table, the footer cells are the last entries of the table's `layout_children` and their fragments are on the last page, below the last body cell.
- Add a `render_smoke` case for T1 and T7 (the fork's CLAUDE.md asks for lib-side tests).

Unchanged and why:

- `convert_table` (`convert/table.rs:58-83`) walks DOM `children`, but it paints each cell at its own layout, so order does not matter. Cells do not overlap.
- F19 row and group areas are unions of the cells' boxes (`:131-176`), so they follow the rows.
- Tagging: `build_struct_tree` orders children by NodeId (`render.rs:5037-5043`), which is DOM order. Reading order stays the author's (THead, TFoot, TBody for T1). That is a non-goal (§6).

**Ours:** lock bump, tests, fixture 20. No API change.

## 6. Risks and non-goals

- **Column widths of `tfoot`-first tables change.** They now come from the first visual row instead of the footer's first row. That is intended, and test 2 pins it against modern order. If Chrome's fixed layout disagrees (step 0), keep column collection in DOM order and only reorder the grid rows; that means a second pass in `build_table_context`, still under one day.
- **F12.** A `thead` after `tbody` now repeats. That matches Chrome but changes output for such tables (no fixture has one).
  - fulgur's `first_table_header_group` reads raw `children` (`blitz_adapter.rs:1088`), while Blitz flattens `display: contents`. A header inside a `contents` wrapper moves to the top but is not repeated: harmless, and not fixed here.
- **F13 / F48.** Alignment is per cell, and extra table height spreads over `auto` rows regardless of their order. Fixture 09 and `fixed_height_cells.rs` / `cell_vertical_align.rs` must stay green and byte-identical.
- **Rebase.** This touches F50's `collect_table_children`. Keep it to one call site.
- **Non-goals:**
  - **F12b, footer repeated per page.** It is not free: the footer needs a band reserved at the bottom of every page but the last, a painted copy, and the ¼-page policy. F36 makes it easier: the footer cells become a suffix of `layout_children`, mirroring F12's prefix.
  - Structure-tree order: it stays DOM order (THead, TFoot, TBody for the HTML4 pattern). F20 will revisit it.
  - Keeping the footer with the last body row at a page break.
  - Row and row-group borders (F22).
  - `visibility: collapse`.
  - Bottom captions (`caption-side`).
