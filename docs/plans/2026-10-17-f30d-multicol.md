# F30d — Multi-column text taller than a page prints nothing

Date: 2026-10-17. Finding: F30d in `2026-10-15-m0-findings.md`. Status: **planned**. Fix goes on `subapavel/fulgur`
`htmltopdf/srgb-colours` (after `e073b6b`), carried via `[patch.crates-io]`.

## 1. Problem

`<div style="column-count:2"><p>` of 4000 words (A4, 15 mm, Inter; `/tmp/claude-0/vrt-f78/ab/mc_normal.html`,
`mc_1.3.html`, `/tmp/claude-0/vrt-f78/s/colmulti.html`) gives 15–22 pages with **0 words** printed and no warning; F30
saw `columns:2` keep 124 of 200 rows (`cols2.html`). Invoice case: a two-column terms block (`columns-2 gap-8 text-xs`)
longer than the room left under the items table loses its text silently. Blitz/Taffy do not lay out multicol (Blitz
treats multicol containers as blocks, `engine.rs:493`); fulgur does it itself, without pages. Root cause (fork, from
reading):

1. `multicol_layout.rs:271-307` `layout_multicol_subtrees` lays each container out once, with Blitz's one-column height
   as `avail_h` (`:282-285`), and balances into one tall column set (`budget` at `:918-935` for Case A — the container is
   itself the inline root — and `:1067-1078` for Case B — `<p>` children). Each column is one `ColumnLineSlice`, many
   pages tall.
2. The paginator treats a multicol container as atomic (`pagination_layout.rs:971-984` body-level, `:2509-2516` nested);
   the fulgur-sbw2 leaf path (`:1123-1144`) cuts it into page strips and records descendants **on the first page only**
   at their unpaged Taffy y (`record_subtree_descendants` `:1404`; "exact mid-element pagination … future work"
   `:1096-1098`), so block children below page 1 are drawn off the page.
3. `render.rs:1583-1601` `paint_multicol_paragraph_slices` skips any slice that "straddles" a fragment break; every slice
   of a 4000-word column straddles one, so no line is painted. fulgur's own test says page-spanning is "not yet
   implemented" (`tests/multicol_integration.rs:87-93`).

Short multicol content that fits its strip goes through none of this; the single-page goldens `multicol-2`,
`-balance`, `-inline-root-split-case-a/b` and the 1-page integration tests suggest it works (not compared with Chrome).

## 2. Spec (cited from memory, unverified)

- css-break-3 §2: column boxes and pages are both fragmentainers (nested fragmentation); §4.1: class A breaks between
  sibling blocks, class B between line boxes; a line box is never split.
- css-multicol-1 §8.2: columns that do not fit the page move to the next page(s).
- css-multicol-1 §7.1 `column-fill: balance`: in fragmented contexts only the **last** fragment is balanced; earlier
  fragments fill column 1 then column 2 to the fragmentainer height; `auto` never balances.
- css-multicol-1 §3–4: used column count / width (`resolve_column_layout`, unchanged) and `column-gap`.

## 3. Design (fulgur fork)

The multicol pass records **what** flows; the paginator decides **where** it goes, once, as index ranges per
(page, column); convert and render use them as given (the F78 rule: no second derivation from heights).

- `multicol_layout.rs`: `ColumnGroupGeometry.flow: Vec<FlowItem>`,
  `enum FlowItem { Block { node: usize, height: Px }, Lines { source: usize, advances: Vec<Px> } }`, filled by
  `layout_column_group` / `layout_self_inline_root_container` with today's predicate (`p` or Case A, glyph runs only,
  per-line `parley_line_heights` — the advances convert already rebases by). Output-neutral.
- `pagination_layout.rs` (pure): `fn plan_multicol_pages(flow: &[FlowItem], n: u32, first_room: f32, page_room: f32,
  fill: ColumnFill) -> Vec<McPage>`; `McPage { height: Px, columns: Vec<Vec<McPiece>> }`,
  `McPiece::{Block { node, y }, Lines { source, first: u32, end: u32, y }}`. Fill columns in order, ≥ 1 unit per column,
  a line never split; when the rest fits n columns of `room` that page is the last — with `balance`, bisect for the
  smallest budget that fits; a block taller than `page_room` is placed alone and overflows with a `log::warn!` naming it.
- `fn fragment_multicol_container(...)`, called from both call sites when the container is multicol, has no
  `column-span: all` child (that path unchanged) and its Taffy height exceeds the room left on its strip (containers that
  fit keep today's path, byte-identical). `first_room` = strip bottom − cursor − top inset; `page_room` =
  `strips.fresh()`; top inset reserved on the first page, bottom inset on the last; if the first unit does not fit
  `first_room` and the cursor is > 0 the container moves to the next page (F28). Records one container fragment per page,
  `PaginationGeometry.multicol_pages: Vec<(u32, McPage)>` on the container, a fragment per `Block` piece at its column x
  and page y (+ that child's subtree), one fragment per page per `Lines` source; returns page and cursor after the last
  fragment.
- `convert/mod.rs` `convert_multicol_paragraph_slices`: with `multicol_pages`, one `ParagraphSlice` per `Lines` piece
  (new `page_index: Option<u32>`), origin relative to the container's fragment on that page, lines rebased by the advances
  before `first`.
- `render.rs` `paint_multicol_paragraph_slices`: a paged slice is painted only on its page, at that page's container
  fragment origin; unpaged slices keep today's logic.
- Scope: `column-count`, `column-width`, `columns`, `column-gap`; body-level and block-nested containers; `<p>` and Case A
  text; atomic block children.
- **F30d-b** (file it): `column-span: all` across pages; `column-rule` per page; child margins inside columns (ignored by
  `layout_column_group` today, so Tailwind `space-y` / `mb-*` vanish there); tables and other blocks taller than a
  column; nested multicol; multicol in flex / grid / table cells; `orphans` / `widows` / `break-inside: avoid` inside
  columns; non-`p` inline roots and paragraphs with inline boxes.

## 4. Acceptance

`crates/htmltopdf/tests/multicol.rs` (A4, default options, Inter, strict, `line-height:20px`, `long_paragraph_pages.rs`
word/bbox helpers; order rebuilt as (page, column by `xMin` vs the gutter, `yMin`)):

1. 4000-word `<p>` and bare text in `column-count:2`, plus `columns:18em`: every word once, column-major; none outside
   the content box; column 2 starts at `col_w + gap` ±1 pt; every page but the last has both columns ending within one
   line of the content bottom; the last page's columns differ by ≤ 1 line; page count ≤ the single-column render's + 1
   (today 15 pages, 0 words). **Red.**
2. Short 2-column text (~150 words) on one page: positions match the Chrome probe within 1 pt (x) and one line (y).
   Guard.
3. A 30-row items table then a 1500-word two-column terms block: first words on page 1 directly below the table (not
   moved whole), every word once, page 2 balanced. **Red.**
4. 30 `<p>` × 150 words (`margin:0`) in two columns over ≈ 3 pages: every word once, column-major. **Red.**

Fork: `plan_multicol_pages` unit tests (lines-only over many pages tile without gaps / repeats; small `first_room`; first
unit does not fit; `auto` vs `balance`; mixed blocks and lines; a block taller than a page; n = 3); lib tests
(fragments, `multicol_pages`); one `render_smoke` (4000 words: every line painted once); tighten
`multicol_page_spanning_renders_without_panic` to ≥ 2 pages.

Fixtures 01–11 byte-identical (none uses multicol). Fulgur VRT: only `multicol-page-spanning` may change (blocks below
page 1 now print on page 2) — re-bless and name it; any other moved golden is a regression; examples byte-identical. New
fixture **`12-terms-columns`**: an invoice with a Czech terms block ≈ 1.3 pages tall,
`<section class="gap-8 text-xs" style="columns:2">` with `<h3>` and `<p>` children (style inline: the compiled
`tailwind.css` has no `columns-2`, precedent fixture 06); Chrome reference committed; threshold = measured + 1.

## 6. Risks and non-goals

- The container's `final_layout` keeps the Taffy height; readers of it (abspos inside multicol, link and bookmark rects)
  may be off on pages after the first — `pdf-reviewer` checks link annotations in sliced paragraphs.
- Chrome applies widows / orphans = 2 in columns, so column ends can differ by a line (accepted, F30d-b).
- Case A opacity and paragraphs with inline boxes stay as today (`render.rs:1470-1481`, `multicol_layout.rs:836-903`).
- Non-goals: everything under F30d-b; `box-decoration-break`; changing the layout of a container that fits its strip.
